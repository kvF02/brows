# Windows 单机可靠性改造

本轮沿用现有 Domain / Application / Ports / Adapters 分层，优先完善正常业务链路之外的生命周期。后续产品设置、受控运行时和指纹实测仍按独立阶段推进。

## 本轮实现

- 桌面进程每 500 ms 查询自有浏览器进程的退出结果。正常退出转为 Stopped，异常退出转为 Failed，清理进程和代理租约，并晋升 FIFO 队列。查询失败保留所有权，等待后续重试。
- Windows 浏览器在挂起状态下创建，加入不可继承、关闭即结束进程树的 Job Object 后再恢复主线程。停止会话和管理器退出均回收自有进程树；管理器异常结束时，OS 关闭 Job 句柄。分配失败时拒绝启动并清理挂起进程。
- 关闭管理器先阻止新启动，再取消排队任务，最后停止活动会话，避免收尾过程中启动新的浏览器。
- 同一数据目录由文件锁限制为一个管理器实例，避免两个进程各自维护调度器并同时写入同一个 Profile。锁随进程结束释放。
- Profile 操作锁由会话、修改、归档、备份和迁移共享。排队与活动会话持续持有锁；数据操作全程持锁，不使用“检查后再操作”的竞态窗口。
- 备份编排移至 BackupApplicationService。运行中、排队中或迁移中的环境不能导出。恢复失败清理暂存数据；新记录先归档，完成数据安装后才解除归档，因此中途退出不会留下可直接启动的半成品。
- 没有 Chrome 或 Chrome 未通过签名验证时，管理服务仍能初始化，保留环境列表和备份入口，并显示修复官方安装、重启管理器的提示。不会降低浏览器信任要求。
- 增加 Linux 可移植检查和 Windows 完整桌面测试的 CI；Windows 进程树测试不依赖本机安装 Chrome。
- 代理 broker 持有所有客户端、上游套接字和连接线程。停止或 Drop 时，关闭双向套接字、唤醒等待名额的连接，并回收监听、连接及隧道双向复制线程；一个 broker 的停止不影响其他会话。
- 每个 broker 最多接受 32 个客户端处理任务，其中最多 6 个同时使用上游。多余连接关闭；等待任务不再无上限创建线程。上游 TCP 连接使用可取消的非阻塞等待，保留原有连接超时；建立隧道后移除两侧握手超时，保留正常半关闭语义。
- 管理器并发上限通过 `settings_get` / `settings_update` 接入真实服务，持久化至 SQLite 的 `manager_settings` 表。数据库迁移至 v6，为原有 v5 数据库增加默认值 10，保留已有 Profile。重启时按已保存上限初始化调度器。
- 保存并发上限后即时生效：提高上限按 FIFO 启动排队会话；降低上限让现有会话自然释放名额，不强行停止它们。写入失败不会改变当前调度器或启动排队任务。退出时停止会话固定开启，遥测固定关闭；自动更新和归档清理策略仍未开放修改。
- 恢复任务在解密前写入 SQLite v7 的 `restore_tasks` 日志，只保存任务 ID、新环境 ID、状态、时间和固定失败类别，不保存口令、归档内容、源路径或异常原文。安装后通过同一个 SQLite 事务启用新环境并完成任务，提交失败时两者一起回滚。
- 启动时在数据目录独占锁内识别未完成恢复，标记为中断并清理暂存；已经完成的任务保持完成状态。未完成的新环境不自动启用，已经安装的数据也不会在清理中删除。任务记录跨重启保留，界面提供中断状态和重试清理入口。
- 备份导出、恢复、手动暂存清理和记录扫描移入阻塞线程池，命令异步等待结果，界面可继续操作。每个管理器只允许一个重型归档任务，最多保留 32 条当前进程的非敏感任务快照；恢复结果仍使用持久化日志。
- 备份页每 750 ms 查询实际阶段和已处理字节数。恢复按读入的归档文件字节计数并显示文件总量；导出按 tar 数据流字节计数，不预估总量或显示虚构百分比。提交和清理完成前均保持进行中。
- 取消与进入提交阶段使用同一把锁判定。导出发布最终归档之前、恢复创建新环境与安装文件之前可以请求取消；进入提交后拒绝取消，等待文件和数据库收尾。I/O 和目录检查设置取消检查点；正在进行的密钥派生和 OS 调用必须先返回，因此取消和正常退出均不承诺固定耗时。
- 正常退出时停止接收备份任务、请求取消未提交的任务，并停止浏览器会话，然后等待后台工作及其资源释放，最后释放数据目录锁。取消导出仅删除本次创建的 `.partial`，既有临时文件保留；取消恢复仍按安全规则清理暂存，清理失败保留标记。
- SQLite v8 增加恢复任务的独立取消状态，保留 v7 历史和既有设置。取消结果跨重启保留，不能再次完成任务或启用目标环境；导出和解密前失败的运行快照仅在本次进程内保留。tar 导出禁用 GNU sparse 条目，使稀疏源文件按恢复器支持的普通文件格式归档。
- 暂存清理限于应用专用目录中的任务目录和旧版随机目录；保留未知内容，拒绝链接、reparse point 及目录穿越。清理失败保留待处理标记并提示，后续可重试；原归档和已有 Profile 不会因此删除。

## 导出与迁移的异常中断恢复

- 新导出使用 `backups/export-staging/<随机 ID>/archive.partial`。启动与手动清理删除可识别的未完成密文和提交后遗留空目录，保留完成归档、未知文件、链接及旧版根目录 `.partial`；旧临时文件无法证明归属，需人工检查或换文件名重试。归档已发布后，空目录清理失败只提示待处理，不把已提交归档改报失败。
- SQLite v9 为迁移增加 `recovery_pending`、`rollback_pending`，在复制与回滚的文件操作之前记录意图。升级时为旧版 running/failed 记录安排检查，保留已有数据、历史与设置。
- 启动在数据目录锁内、开放会话之前逐环境恢复。未完成迁移优先还原原 userdata；已经安装但未提交的新版本改存 `userdata.interrupted-migration-<ID>`，不删除。回滚中断后继续完成两次重命名并保留迁移版本，再确认日志。恢复不读取原 MoreLogin 缓存，不需要其安装或源环境仍存在。
- 无法判断的布局、链接或清理错误保留数据，并持续占用相关环境的操作锁，禁止启动、编辑或再迁移。其他环境继续可管理；备份页显示待恢复提示，提供“重试数据恢复与清理”。同一环境有多条待处理记录时，从新到旧处理，全部完成才释放锁。旧任务之后若有更新的已提交迁移，保留当前数据并锁定待人工检查，不用旧备份覆盖新版本。
- 回归覆盖复制前后、旧数据改名、新数据安装、恢复两次改名之间、已提交迁移、回滚两次改名之间，以及重启后的重复检查。旧版没有记录回滚意图的已中断回滚无法可靠推断；不能把本次恢复实现视为整机断电验收或完整迁移续传。

## 自动检查

从仓库根目录运行：

```sh
npm ci --prefix ui
npm run ui:build
npm run test:fingerprint
npm run test:settings
npm run test:backups
cargo +1.97.1 fmt --all -- --check
cargo +1.97.1 test --locked --workspace --exclude brows-desktop
cargo +1.97.1 clippy --locked --workspace --exclude brows-desktop --all-targets -- -D warnings
```

Windows 还应运行 `cargo +1.97.1 test --locked --workspace` 和完整 workspace Clippy。新增测试覆盖正常退出/崩溃后晋升、关闭管理器不晋升、运行及排队时的数据锁、备份中的并发启动、恢复失败归档与暂存清理，以及缺失/不可信 Chrome 时继续管理和数据目录独占。进程树测试创建专用子进程及孙进程，验证停止和 Drop 后它们退出；测试辅助入口标记为 ignored，仅由父测试在隔离子进程中调用。

代理套接字回归可独立运行 `cargo +1.97.1 test --locked -p brows-adapters-proxy`。本机通过 15 项测试，覆盖取消与套接字登记竞态、握手和既有隧道的停止、等待名额的唤醒、客户端数量上限、Drop 收尾、会话间隔离、空闲隧道与半关闭，以及上游失败时不直连目标。代理代码及测试也通过 Windows 目标的交叉 Clippy 检查；Windows 实际套接字行为由 CI/实机测试验证。

## Windows 实机验收与后续工作

交叉编译和内存适配器测试不能代替真实 Chrome 验收。需要在 Windows 上执行以下场景并记录运行时版本、结果及残留进程：

1. 十个真实环境并发，第十一个排队；手动关闭其中一个后，排队环境启动。
2. 浏览器异常退出后状态更新、代理租约释放；允许重新启动同一环境。
3. 关闭管理器时队列不启动，所有自有浏览器进程树退出；强制结束管理器后重新打开，不残留自有浏览器或数据锁。
4. 运行与排队期间，备份、迁移、归档被拒绝；停止后可以重试。
5. 错误口令、磁盘空间不足、数据安装失败以及恢复过程中强制退出；原环境不被覆盖，未完成记录保持归档。
6. 卸载或修复 Chrome 后，管理器能打开并提示；安装修复后重启，重新执行可信验证。
7. 有排队任务时调高、调低并发上限，确认 FIFO 补位和自然降载；重启后保留设置。数据库写入失败时显示错误，当前会话与排队状态保持原样。
8. 在解密、记录目标身份、创建归档环境、安装文件、提交完成记录这五个边界强制退出；重启后确认未完成任务显示中断、未启用新环境，已完成任务不降级；原环境、已安装数据及源归档不被删除。

9. 大文件导出、恢复期间切换页面并查询进度；处理中取消后等待清理，确认原环境和源归档保留。取消与提交同时发生时，只能出现“取消并清理”或“提交完成”之一；提交后拒绝取消。密钥计算期间和关闭窗口时，等待当前计算或 OS 调用返回后再完成收尾。

代理停止仍可能等待操作系统的同步 DNS 解析返回，包括代理主机和 SOCKS5 本地解析模式的目标主机；解析返回后会检查取消，不再建立新连接。不能把套接字取消的检查间隔当成整个停止操作的硬性超时。后续若要求严格停止时限，需要独立设计可取消的解析器。

设置回归覆盖真实命令转发、错误传播、数值和固定策略校验、FIFO 调整、写入失败、v5 升级及重启恢复。浏览器开发的 Mock 使用相同的并发调整规则；页面不再提供无法兑现的退出策略开关。

恢复回归覆盖事务回滚、完成记录不可降级、清理失败重试、v6 升级、真实加密归档恢复，以及五种持久化边界的重复启动模拟。模拟持久化状态不代表 Windows 实机强杀或整机断电验收。链接防护测试在 Windows 测试机上需要开发者模式或创建目录符号链接的权限；产品正常运行不依赖该测试权限。

恢复密码不持久化，重启后不会自动继续解密。暂存删除失败时可能仍保留解密文件，并在界面显示待清理；已安装但尚未提交完成的新环境保持归档，保留数据供检查。启动时的中断恢复仍需完成检查后才打开窗口；手动清理已进入后台，但开始删除后不再接受取消。

本轮自动验证通过 151 项可移植 Rust 测试、20 项桌面测试（另有 2 项真实 Chrome 测试需手动启用）和 25 项 JavaScript 测试，以及前端构建、完整 workspace 的严格 Clippy 和应用/备份/迁移适配器的 Windows 目标交叉 Clippy。新增回归覆盖大文件实际 I/O 中取消、提交与取消竞争、既有临时文件保护、稀疏文件恢复、取消后的清理重试、v7 到 v8 历史保留、后台执行时查询与取消、退出等待后台资源释放，以及迁移/回滚中断恢复、待恢复环境锁定、v8 到 v9 升级与重复重启。

仍需跟进：Windows 实机强杀与断电验收；迁移等其余耗时操作的异步进度与取消；前端创建时间、诊断摘要等数据展示；依赖审计中的已知告警；可信且支持扩展注入的运行时与真实指纹观测矩阵。本轮不将这些条目视为已验收。
