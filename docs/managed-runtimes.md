# 本机托管运行时

设置页可以将已登记的稳定版 Chrome/Edge 保存为独立版本快照。IPC 只接受运行时 ID，
不能传入可执行文件路径、下载 URL、命令行或任意安装脚本。

快照来源经过既有签名准入，再核对可执行文件的原生 Windows 文件版本；目录名称不作为
版本事实。复制当前版本目录及安装根资源，跳过其他数字版本目录和安装器的临时 SetupMetrics 统计数据，拒绝符号链接和重解析点。
每份快照限制 20,000 个文件、4 GiB、32 层目录。

复制到独立 staging 目录，每个文件核对复制前、复制后与目标 SHA-256。重新验证来源与
目标可执行文件的发行者和文件版本后，写入有大小上限的清单，通过同卷 rename 发布。
失败清理 staging，不覆盖已有版本。ID 绑定供应商、原生版本及完整文件清单摘要。

Windows 快照目录授予 `ALL RESTRICTED APPLICATION PACKAGES` 读取/执行权限，让
Chromium LPAC 子进程能够加载自身二进制和资源。权限只作用于经过验证的快照子树，
不修改父目录、Profile、数据库或凭据目录；不授予写权限，不关闭浏览器沙箱。
依据：[Chromium 官方 LPAC 文件权限说明](https://chromium.googlesource.com/chromium/src/+/main/docs/design/sandbox.md)。

已保存版本可并存；应用重启后重新准入，每次启动或能力探针前重新核对全部资源文件。
资源变更、额外 DLL、文件丢失均拒绝启动。SetupMetrics 仅在来源选取时排除，已发布目录仍执行完整清单校验，不增加运行时忽略目录。损坏快照排除出登记表，固定到它的环境不会
自动改用其他版本。当前不提供自动修复或删除快照的 UI。

## 选择与数据兼容

只有停止所有运行及排队会话后才能切换默认版本，选择保存到 SQLite。
默认版本只影响按通道选择的环境；固定版本环境不随默认选择变化。
每份快照的指纹支持初始为未验证，必须单独运行能力探针。快照通过私有控制器读取页面首段脚本捕获的固定字段，不依赖搬移后可能不加载的 MV3；只有真实观测匹配才允许 SeedableNoise。

对 Chrome/Edge，首次受此版本管理的启动会在 Profile 目录留下只追加的版本记录。
后续禁止同一目录切换浏览器家族或降低原生四段版本号；使用旧内核应创建新环境，或
恢复与旧内核相符的备份。启动失败也可能保留更高版本记录，这是保守的准入决定。
历史上没有记录的目录，只能从首次登记开始约束，无法重建它此前使用过的内核版本。

本机安装项仍由供应商更新器维护，固定其登记 ID 不等于固定磁盘上的版本。
需要固定内核时，明确选择托管快照的不可变 ID。

## 信任与更新边界

清单是**本机完整性基线**，不是厂商或项目签名的发布目录，不能抵抗已控制同一
Windows 用户的攻击者。资源来源信任继承自现有本机安装；只对主可执行文件执行
Authenticode 发布者验证，不声称所有资源逐个获得厂商签名。

没有自动下载、项目更新密钥、在线吊销新鲜度或强制安全最低版本目录。
升级路径为：正常更新厂商浏览器 → 重新启动 Brows 登记新安装版本 → 保存新快照 →
重新验证能力 → 在备份后逐步迁移环境。旧快照不会自动获得安全更新。
长期锁定旧版本不是安全更新策略；引入可信下载和签名发布目录仍是独立后续阶段。

这项工作不修改 Chromium 内核，不增加字体、真实 GPU、实时音频或 TLS/HTTP2 覆盖。
实际安装、快照和容量验收状态以对应提交的 Windows CI 报告为准。
